# AI 漫剧创作工作台
## 产品需求文档（PRD）与技术开发计划

**项目名称：** AI Comic Studio  
**项目定位：** AI 漫剧创作与视频生产平台  
**项目版本：** V1.0 MVP  
**项目周期：** 6～8 周  
**开发模式：** 前后端协同、模块化开发、逐步接入 AI 能力

---

# 一、项目背景与目标

## 1.1 项目背景

随着大语言模型、图像生成模型和视频生成模型的发展，传统影视内容生产流程正在逐步向 AI 辅助创作转变。

本项目参考 WorkRally 等 AI 内容生产平台，开发一套从剧本创作到视频生成的 AI 漫剧工作台。

平台通过 AI Agent 和多模型协作，将传统内容生产流程拆解成多个可管理、可编辑、可追踪的任务。

## 1.2 产品目标

建立完整的 AI 漫剧生产链路：

1. 用户输入故事文本或创作大纲。
2. AI 自动分析和拆解剧本。
3. AI 提取人物、场景和道具。
4. 生成角色设定及参考图片。
5. 生成分镜脚本和镜头描述。
6. 根据分镜生成关键帧图片。
7. 根据关键帧生成视频片段。
8. 通过时间轴完成镜头编排。
9. 生成配音、字幕及背景音频。
10. 合成并导出最终视频。

## 1.3 MVP 核心目标

第一版不追求完整的商业化视频编辑能力，重点验证以下能力：

- 完整的项目和剧集管理。
- AI 剧本结构化拆解。
- 角色与场景资产管理。
- AI 分镜生成。
- 图片生成和视频生成。
- 异步任务管理。
- 视频素材预览和基础合成。

**第一版优先接入第三方模型 API 或成熟开源模型，不以从零训练视频模型为前提。**

- 项目描述
- 项目封面

- 更新时间
- 项目状态

- 可以创建、编辑和删除项目。
- 项目数据持久化。
- 可以进入指定项目的创作工作台。

## 2.2 剧集管理（Episode Management）

### 功能需求

- 一个项目支持多个剧集。
- 创建、编辑、删除剧集。

- 剧集生成状态管理。

### 验收标准

- 一个项目可以管理多个剧集。
- 剧集与所属项目建立关联。
- 剧集可以独立进行 AI 拆解。

## 2.3 AI 剧本拆解（Script Agent）

这是整个系统的核心入口。

### 输入

- 小说文本。
- 故事大纲。
- 用户自定义剧本。
- 剧集文本。

### AI 处理流程

1. 分析故事内容。
2. 提取故事背景。
3. 提取人物信息。
4. 分析人物关系。
5. 提取场景信息。
6. 拆分剧情段落。
7. 生成结构化剧本。
8. 生成分镜所需的上下文信息。

### 输出结构

- 故事简介。
- 故事大纲。
- 剧集信息。
- 人物列表。
- 人物关系。
- 场景列表。
- 剧情段落。
- 对白信息。

### 验收标准

- 可以将普通文本提交给 AI。
- AI 返回符合约定 Schema 的 JSON。
- 解析结果可以展示和编辑。
- 支持重新生成。
- 支持保存和版本管理。
- AI 输出不符合结构时具备错误处理和修复机制。

## 2.4 角色资产管理（Character Management）

### 功能需求

- 自动提取角色。
- 创建角色。
- 编辑角色资料。

- 角色性格和背景。

- 角色参考图片生成。
- 多版本图片管理。
- 设置默认参考图。
- 角色与剧集、场景关联。

### 核心数据

- 角色名称。
- 角色简介。
- 外貌描述。
- 年龄设定。
- 性格特征。
- 服装设定。

- 角色状态。

### 验收标准

- 可以生成角色参考图。
- 可以保存多个角色图片版本。
- 分镜生成时可以引用角色资产。

## 3.3 AI 模型层

第一版采用统一模型适配器设计。

模型类别：

- LLM：剧本拆解、内容生成。
- Image Model：角色和场景图片。
- Video Model：视频生成。
- TTS：语音合成。
- Audio Model：音乐和音效。

建议抽象统一接口，避免业务代码直接依赖某个模型厂商。

例如：

generate_text()
generate_image()
generate_video()
generate_audio()

未来可以替换第三方模型、部署开源模型或接入公司自己的模型服务。

## 3.4 媒体处理层

- FFmpeg：视频处理和合成。
- 对象存储：图片、视频和音频存储。
- Redis：任务状态和队列。
- PostgreSQL：业务数据持久化。

# 四、核心业务流程

## 4.1 剧本拆解流程

用户输入剧本
→ 后端创建拆解任务
→ LLM 分析剧本
→ 生成结构化 JSON
→ 数据校验
→ 保存剧集、角色、场景
→ 前端展示拆解结果
→ 用户确认和修改

## 4.2 分镜生成流程

读取剧本
→ 获取角色资产
→ 获取场景资产
→ AI 生成镜头列表
→ 校验分镜数据
→ 保存分镜
→ 用户编辑确认

## 4.3 图片生成流程

用户选择分镜
→ 读取角色参考图
→ 读取场景参考图
→ 组合提示词
→ 调用图片模型
→ 创建异步任务
→ 保存图片
→ 更新分镜结果

## 4.4 视频生成流程

用户选择分镜
→ 读取关键帧
→ 获取视频提示词
→ 调用视频模型
→ 创建任务
→ 追踪任务状态
→ 获取生成结果
→ 保存视频
→ 关联分镜

## 4.5 视频合成流程

读取镜头列表
→ 获取视频素材
→ 根据时间轴排序
→ 处理音频和字幕
→ FFmpeg 合成
→ 生成最终视频
→ 保存导出文件

# 八、非功能性需求

## 8.1 稳定性

- AI 生成任务支持异步执行。
- 服务异常后可以恢复任务状态。
- 任务失败支持重试。
- 防止重复提交。
- 记录任务执行日志。

## 8.2 性能

- 大型视频文件采用对象存储。
- 视频预览采用流式或分段加载。
- 列表数据分页。
- 大型画布支持必要的渲染优化。
- AI 任务不能阻塞普通 API 请求。

## 8.3 安全

- 模型 API Key 保存在服务端。
- 文件上传进行类型和大小校验。
- 用户只能访问授权项目。
- 视频和图片资源具备访问权限控制。
- 生成任务进行用户归属校验。

## 8.4 可扩展性

- 支持多个模型供应商。
- 支持不同模型版本。
- 支持工作流扩展。
- 支持后续自部署模型。
- 支持不同视频生成任务类型。

# 九、MVP 验收标准

最终至少完成以下完整闭环：

1. 创建一个漫剧项目。
2. 输入一段故事文本。
3. AI 自动拆解剧本。
4. 自动提取角色和场景。
5. 生成角色和场景参考图片。
6. AI 自动生成分镜。
7. 用户可以编辑分镜。
8. 根据分镜生成图片。
9. 根据图片生成视频。
10. 将多个视频片段加入时间轴。
11. 合成并导出 MP4 文件。

**最终验收：用户能够独立完成从故事文本到视频成片的基本生产流程。**

# 十一、项目开发原则

1. 先完成核心业务闭环，再扩展复杂功能。
2. 先使用成熟模型，不从零训练视频模型。
3. AI 模型接入必须通过统一适配层。
4. 所有耗时生成操作采用异步任务。
5. 角色、场景、分镜和素材必须建立明确关联。
6. 生成结果支持版本管理，不直接覆盖。
7. 前端、后端和 AI 服务保持职责分离。
8. 每个开发阶段都必须有可运行、可验收的交付物。

**项目最终目标：建立一套模块化、可扩展、模型无关的 AI 漫剧生产工作台，为后续接入自有模型和 GPU 推理服务预留架构空间。**
